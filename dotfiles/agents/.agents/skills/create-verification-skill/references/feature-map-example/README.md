# Feature map

Keep one Markdown file per user-facing feature. Link every file here and remove dead links during maintenance.

Each feature file uses these sections:

## Sub-features

Name the distinct user outcomes covered by this file.

## How to get to it (user POV)

Give the route, menu, command, or setup journey. Include test-data prerequisites.

## Driving it with the verification harness

Give the exact actions and stable targets. Name what to observe after each action.

## Gotchas

Record required roles, seed state, timing constraints, external dependencies, and known unreachable paths. A missing prerequisite is not permission to skip an assertion.
