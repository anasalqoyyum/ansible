# Prototype

You own the decision the prototype makes possible.

1. Write the single question and the observable result that would answer it.
2. Choose the cheapest artifact and real-enough surface for that observation.
3. Build only the path needed to answer the question. Mark shortcuts and unsupported cases.
4. Run it. Capture the result rather than describing expected behavior.
5. Compare alternatives when the question is about design shape.
6. Decide what the evidence supports, rejects, or leaves unresolved.
7. Keep the prototype only when the user asks or deliberately promotes it. Otherwise remove or isolate it.

Completion is an evidence-backed decision, not production readiness. No PR unless publication was explicitly requested.
