# Investigation

You own the cited answer. Use for read-only questions about behavior, architecture, history, or whether an approach is sound.

1. Define the exact question and the evidence that could answer it.
2. Route through `how` for architecture and `why` when historical intent matters.
3. Trace the relevant code, data flow, runtime evidence, and durable history. Separate observations from inference.
4. If a reversible experiment can settle a technical fork, run the smallest prototype. Stay read-only when the requested deliverable is a cited answer.
5. Test competing explanations against the evidence. State what remains unknown.
6. Hand back the answer with file, symbol, command, PR, issue, or documentation citations actually inspected.

Do not open a PR or implement a fix. If the investigation should become a change, re-route to Bug fix, Performance issue, Feature, or Refactoring.
