# tstack skills review

Reviewed [`t3dotgg/tstack`](https://github.com/t3dotgg/tstack) at `main` commit [`1085050f3baed1ac724caa4a8166145fb2ac88af`](https://github.com/t3dotgg/tstack/commit/1085050f3baed1ac724caa4a8166145fb2ac88af), dated 2026-10-28. The pinned tree contains nine skills, one `babysit-pr` script, and four `agents/openai.yaml` metadata files. The README says the skills target Claude Code and Codex, with some T3 Code features and native fallbacks. It also requires authenticated `gh`, Python for the watcher, and cross-provider agents for `council` and `sol-loop` ([README](https://github.com/t3dotgg/tstack/blob/1085050f3baed1ac724caa4a8166145fb2ac88af/README.md#L3-L6), [requirements and dependencies](https://github.com/t3dotgg/tstack/blob/1085050f3baed1ac724caa4a8166145fb2ac88af/README.md#L22-L43)).

## Recommendation

Do not copy the collection wholesale. The local `babysit`, `pr`, and `lazy` workflows already support GitHub and Bitbucket. Local `implement` covers spec-based work, TDD, checks, code review, and commit; Lazy supplies the separate PR and shipping path ([implement](../../dotfiles/agents/.agents/skills/implement/SKILL.md#L7-L17), [Lazy playbooks](../../dotfiles/agents/.agents/skills/lazy/SKILL.md#L110-L145)). Lazy also has autonomous-run, babysit, shipping, and autopilot playbooks that cover most of the unattended lifecycle ([babysit](../../dotfiles/agents/.agents/skills/babysit/SKILL.md#L10-L29), [PR drafting](../../dotfiles/agents/.agents/skills/pr/SKILL.md#L12-L18), [Lazy autonomy and host routing](../../dotfiles/agents/.agents/skills/lazy/SKILL.md#L72-L95), [autopilot full](../../dotfiles/agents/.agents/skills/lazy/playbooks/autopilot-full.md#L3-L14)). Local verification guidance already asks for direct proof of the real artifact and has skills to create or maintain project-specific live verification workflows ([proof](../../dotfiles/agents/.agents/skills/principle-prove-it-works/SKILL.md#L9-L31), [create verification](../../dotfiles/agents/.agents/skills/create-verification-skill/SKILL.md#L7-L41), [maintain verification](../../dotfiles/agents/.agents/skills/maintain-verification-skill/SKILL.md#L11-L27)).

The strongest additions are concepts to adapt: `takeover` preserves authorship and reconstructs the inherited goal; `modernize` judges whether an old PR still belongs before rebasing; `full-send` lays out a complete proof, review, PR, babysit, and merge path. The bundled watcher needs fixes before reuse. Tstack is GitHub-only in practice. Local guidance routes GitHub through connected tools or `gh`, Bitbucket through `bkt`, and does not let a skill grant authority for publishing or other external changes ([platform policy](../../dotfiles/agents/.agents/skills/lazy/SKILL.md#L88-L95), [authorization policy](../../dotfiles/agents/.agents/AGENTS.md#L3-L17)).

## Fit for unattended work

The most useful change would be a clear entry point that connects the existing skills. Local `implement` ends at a commit, `pr` drafts rather than publishes, and `babysit` starts from an existing PR. Lazy already has the broader workflow, but its frontmatter requires explicit invocation. Tstack makes the intended finish easier to request with `full-send` and `full-stop`. Adapt those as short entry points over the existing host-aware skills, with one shared lifecycle and two finish conditions: merge-ready or merged. Keep verification tied to the current head and use durable watcher wakeups while CI or reviews are pending. An opened PR or enabled auto-merge is not the merged finish condition ([local implement](../../dotfiles/agents/.agents/skills/implement/SKILL.md#L7-L17), [local PR scope](../../dotfiles/agents/.agents/skills/pr/SKILL.md#L6-L8), [Lazy invocation](../../dotfiles/agents/.agents/skills/lazy/SKILL.md#L1-L5), [upstream lifecycle](https://github.com/t3dotgg/tstack/blob/1085050f3baed1ac724caa4a8166145fb2ac88af/skills/full-send/SKILL.md#L43-L98)).

A deliberate user invocation can communicate an agreed workflow and its scope. The adaptation should define that meaning clearly and honor existing session authority throughout, without treating arbitrary task text as permission. In particular, upstream `full-stop` explicitly triggers even when the words are ordinary emphasis. Remove that trigger. It also disables existing auto-merge and removes merge-queue entries, which needs a defined scope before use ([trigger and queue mutations](https://github.com/t3dotgg/tstack/blob/1085050f3baed1ac724caa4a8166145fb2ac88af/skills/full-stop/SKILL.md#L1-L27)).

Use the bounded review loop from `sol-loop` with the configured reviewer, rather than hardwiring GPT Sol. Borrow its three-round default, stable finding IDs, checks after fixes, and explicit unresolved result when the budget ends. Do not import its rule that rare cases are always nits; judge security and correctness against the actual contract. The user-provided agent model rule takes precedence over Lazy's current-model rule ([review budget](https://github.com/t3dotgg/tstack/blob/1085050f3baed1ac724caa4a8166145fb2ac88af/skills/sol-loop/SKILL.md#L15-L25), [finding triage](https://github.com/t3dotgg/tstack/blob/1085050f3baed1ac724caa4a8166145fb2ac88af/skills/sol-loop/SKILL.md#L80-L98), [local agent model rule](../../dotfiles/agents/.agents/AGENTS.md#L34-L38)).

The checked-out collection and deployed collection agree on `babysit`, `pr`, `implement`, `code-review`, `autonomous-run`, and `session-pickup`. Deployed Lazy and Shipping have older wording, but the same relevant host routing and finish boundaries. This review's repository links target the checked-out collection. No skills were installed or changed.

## Portability, autonomy, and license

- The tstack README installation copies every skill to Claude Code or Codex skill directories, but the PR workflows are built around GitHub. The README requires `gh`; `pr-wait` accepts GitHub PR URLs and invokes GitHub CLI/API calls. It has no Bitbucket Cloud or Data Center path ([requirements](https://github.com/t3dotgg/tstack/blob/1085050f3baed1ac724caa4a8166145fb2ac88af/README.md#L29-L43), [target parsing and GitHub calls](https://github.com/t3dotgg/tstack/blob/1085050f3baed1ac724caa4a8166145fb2ac88af/skills/babysit-pr/scripts/pr-wait#L178-L211)). Local skills explicitly distinguish GitHub from Bitbucket Cloud and Data Center ([local host routing](../../dotfiles/agents/.agents/skills/lazy/SKILL.md#L88-L95), [Bitbucket commands](../../dotfiles/agents/.agents/skills/babysit/SKILL.md#L92-L197)).
- `full-send` matches the user's preference for an agent that owns a task through a terminal result. Its strongest contribution is the explicit sequence and proof gate, not an automatic grant of permissions. Local `autonomous-run` already says to define a checkable finish condition, use event-driven wakeups when available, continue authorized work, and report evidence ([local autonomous run](../../dotfiles/agents/.agents/skills/lazy/playbooks/autonomous-run.md#L1-L11)).
